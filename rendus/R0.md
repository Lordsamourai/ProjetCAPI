## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---|
| Portée et niveau | application CAPI · utilisateur |
| Acteur principal | Scrum Master |
| Intervenants et intérêts | Scrum Master : configure et participe a une partie afin d'obtenir un backlog estimé à la fin.<br><br> Joueurs : voter sans révéler son choix avant la fin du tour, obtenir une estimation sur la fonctionnalité abordée, obtenir un backlog estimé à la fin |
| Déclencheur | Le Scrum Master démarre une partie pour estimer un backlog |
| Garanties | Minimales : Les estimations non votées ne sont pas prises en compte, la règle reste sauvegardée dans le JSON.<br><br> De succès : Le système crée un JSON du backlog avec chaque tâche estimée lors de la session de planning poker |

### Scénario nominal (5 à 7 étapes)

1. Le Scrum Master configure la partie
2. Le système charge le backlog
3. Les joueurs rejoignent la partie
4. Les joueurs sélectionnent une carte
5. Le système révèle les cartes
6. Le système calcule l’estimation du backlog
7. Le système enregistre l’estimation et exporte le backlog en json

### Extensions (3 obligatoires)

2a. Le backlog chargé est invalide :
  - 2a1. Le système affiche un message d’échec du chargement
  - 2a2. L’utilisateur peut choisir un backlog a charger

2b. L'utilisateur reprend une partie sauvegardée :
  - 2b1. Le système charge la partie sauvegardée
  - 2b2. L’utilisateur rejoint la partie et reprend l’estimation en cours

4a. Tous les joueurs jouent la carte café :
  - 4a1. Le système annule le calcul de l’estimation
  - 4a2. Le système sauvegarde l’état d’avancement

## 2. Les 6 user stories

| US | Texte (En tant que... je veux... afin de...) | Source | MoSCoW |
|---|---|---|---|
| US-01 | En tant que scrum master, je veux que le système permette de charger un backlog afin de pouvoir démarrer une session d’estimation. | CU-01 étape 2 | Must |
| US-02 | En tant que joueur, je veux que l’estimation soit validée en utilisant la médiane afin d’avoir une valeur qui représente le mieux le vote. | Fonctionnalité numéro 5 | Should |
| US-03 | En tant que joueur, je veux que l’estimation du premier tour soit validée uniquement si les votes sont unanimes afin de permettre un dialogue en cas de désaccord.| Fonctionnalité numéro 5 | Must |
| US-04 | En tant que joueur, je veux que le système applique une règle stricte afin de valider l’estimation uniquement si tous les votes sont identiques. | CU-01 étape 5 | Must |
| US-05 | En tant que Scrum Master, je veux charger une session sauvegardée, puis pouvoir modifier les votes et exporter le backlog en JSON afin de pouvoir gérer une partie de planning poker. | CU-01 extension 2b | Should |
| US-06 | En tant que joueur, je veux voter secrètement afin de ne pas être tenté de changer mon vote. | CU-01 étape 3 | Must |

Parmi ces 6 US, 3 portent les règles de validation : règle stricte, règle choisie, premier tour à l'unanimité.
